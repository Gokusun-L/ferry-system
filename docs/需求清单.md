# 需求清单与实现对照

> 依据《数据库应用实践》任务书，对源码、SQL、页面逐条核对生成，不是设计稿。
> 版本：v1.0　日期：2026-11-26　对应代码：`main` 分支

## 0. 怎么用这份文档

- **验收**：按编号逐行核对任务书要求，右侧两列给出实现位置和验证方式。
- **交接**：新成员先读《核心业务流程说明》，再用本表定位自己负责的代码。
- **改需求**：先在本表找到对应行，再按“实现位置”修改，避免漏改页面或接口。

状态说明：

| 标记 | 含义 |
|---|---|
| 已实现 | 功能完整，有自动化测试或可按手工路径验证 |
| 模拟实现 | 业务闭环完整，但外部能力用模拟替代（支付、打印、二维码） |
| 扩展实现 | 任务书未强制要求，为业务完整性补充 |

验证方式中的测试类位于 `src/test/java/com/ferry/`。运行测试前先执行 `sql/90_test_schema.sql` 建 `ferry_test` 库，并确认 `src/test/resources/application-test.yml` 的账号密码；然后执行 `mvn test`。

## 8. 最短验收路径

按以下顺序走一遍，可覆盖主要需求：

1. **管理员**：`admin/123456` 登录 → 建航线 → 建船舶（自动生成座位）→ 建班次 → 发布 → 班次详情看余座。
2. **乘客**：`zhangsan/123456` 登录 → 搜索班次 → 选座（观察 5 分钟锁定与总价）→ 下单 → 我的订单支付 → 查看船票。
3. **退改签**：同一乘客对已支付订单发起改签（换班次/座位），再对另一张票发起退票，核对退款金额与通知。
4. **售票员**：`seller1/123456` 登录 → 线下售票并打印 → 检票（输入票号/订单号）→ 查看检票统计 → 个人业绩。
5. **管理员统计**：选择日期范围 → 查看日/周/月收入、航线上座率、低上座率预警、退票原因 → 导出 Excel → 打印预览。
6. **异常路径**：重复身份证购票、同一座位并发下单、支付超时、发船后退票、发船前 1 小时内改签，均应给出明确提示。

## 9. 实现口径与已知边界

| 项目 | 口径 |
|---|---|
| 支付 | 模拟支付，无第三方支付网关与支付流水表 |
