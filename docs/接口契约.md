# ferry-system 接口契约

> 依据源码逐接口核对生成，不是设计稿。
> 版本：v1.0 　状态：已冻结 　日期：2026-11-25
> 后端：Spring Boot 3.2.5 + Thymeleaf + MyBatis + MySQL

## 0. 这份文档怎么用

前端改页面时，**以本文档为准**，不要从模板里的旧 JS 反推接口。
判定标准：照着本文档能写出全部请求和渲染逻辑，中途不需要问后端。

## 1. 全局约定

### 1.1 运行形态

| 项 | 现状 | 对前端的影响 |
|---|---|---|
| 部署方式 | 单体应用，Thymeleaf 服务端渲染 + REST 接口同源 | 无跨域，不需要配 CORS |
| 认证方式 | Session Cookie（`JSESSIONID`），登录态存 session 的 `loginUser` | **不是 token**，fetch 必须带 `credentials: 'same-origin'` |
| 页面路由 | 返回 HTML | 由后端 `PageController` 控制 |
| 接口路由 | `/api/**` 返回 JSON | 前端 fetch 调用 |

### 1.2 统一响应结构

```json
{ "code": 0, "msg": "success", "data": null }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | `0` 成功；`1` 业务失败；`403` 无权限 |
| msg | string | 错误提示，**字段名是 msg，不是 message** |
| data | 任意 | 失败时为 `null` |

### 1.3 HTTP 状态码语义（重点）

这是本项目最容易踩坑的地方。

| 场景 | HTTP 状态 | 响应体 |
|---|---|---|
| 业务成功 | 200 | `{code:0, data:...}` |
| 业务失败（参数错、状态冲突、库存不足等） | **400** | `{code:1, msg:"..."}` |
| 参数校验失败（@Valid / JSON 解析失败） | **400** | `{code:1, msg:"..."}` |
| 服务端异常 | **500** | `{code:1, msg:"系统异常，请稍后重试"}` |
| 角色无权限（已登录） | 403 | `{code:403, msg:"无权限访问", data:null}` |
| 未登录访问 `/api/**` | **401** | `{code:401, msg:"未登录", data:null}` |

结论：HTTP 状态码已按语义返回，但**业务结果仍然只看 `code === 0`**。

前端 `common.js` 的 `api()` 已统一处理：响应 `content-type` 不是 JSON 时直接跳登录页，避免拿到 HTML 后解析异常。

### 1.4 时间与金额格式

| 类型 | JSON 表现 | 说明 |
|---|---|---|
| LocalDateTime | `"2026-11-25T08:30:00"` | Jackson 默认 ISO-8601，带 `T`，前端展示需自行替换 |
| LocalDate 入参 | `"2026-11-25"` | 查询参数统一 `YYYY-MM-DD` |
| BigDecimal（price / totalAmount） | JSON 数字，如 `160.00` | 不要当字符串处理 |

### 1.5 分页约定

| 项 | 约定 |
|---|---|
| 入参 | `page` 从 1 开始，默认 1；`size` 默认 10 |
| 出参 | `{ "list": [...], "total": 123, "page": 1, "size": 10 }` |
| 适用 | users / routes / ships / schedules / orders 全部分页 |
| 特例 | `/api/*/all` 与 `/api/tickets/my` 不分页，直接返回数组；notifications 额外返回 `unread` |

### 1.6 角色与鉴权

角色枚举：`ADMIN`（管理员）、`SELLER`（售票员）、`PASSENGER`（乘客）。

| 拦截器 | 范围 | 行为 |
|---|---|---|
| LoginInterceptor | `/**`，放行 `/login` `/register` `/css/**` `/js/**` `/error` | `/api/**` 未登录 → 401 JSON；页面未登录 → 302 到 `/login` |
| RoleInterceptor | 同上 | 已登录但角色不符 → `/api/**` 返回 403 JSON；页面重定向 `/` |

方法级 `@RequireRole` 优先于类级，方法未标注时继承类级注解。

### 1.7 枚举字典

**订单状态 `order.status`**

| 值 | 含义 |
|---|---|
| UNPAID | 待支付 |
| PAID | 已支付 |
| CHECKED | 部分/全部已检票 |
| FINISHED | 已完成 |
| CANCELLED | 已取消 |
| REFUNDED | 已退票 |

**船票状态 `ticket.status`**

| 值 | 含义 |
|---|---|
| UNPAID | 待支付 |
| PAID | 已支付 |
| CHECKED | 已检票 |
| REFUNDED | 已退票 |
| CANCELLED | 已取消 |
| RESCHEDULED | 已改签（原票作废） |

**座位状态 `scheduleSeat.status`**

| 值 | 含义 | 前端表现 |
|---|---|---|
| AVAILABLE | 可售 | 可选 |
| LOCKED | 被锁定 | 不可选；`lockUserId` 等于当前用户时可视为"我已选" |
| SOLD | 已售 | 不可选 |

**班次状态 `schedule.status`**

| 值 | 含义 |
|---|---|
| PENDING | 已建未发布 |
| SELLING | 售票中 |
| DEPARTED | 已发船 |
| FINISHED | 已完成 |
| CANCELLED | 已取消 |

**其他**

| 字段 | 取值 |
|---|---|
| `order.channel` | ONLINE / OFFLINE |
| `user.role` | ADMIN / SELLER / PASSENGER |
| `user.status` | 1 正常 / 0 禁用 |
| `notification.type` | SCHEDULE_CANCEL / REFUND_SUCCESS / RESCHEDULE |
| `notification.isRead` | 0 未读 / 1 已读 |

### 1.8 业务常量（前端提示文案要对齐）

| 规则 | 值 |
|---|---|
| 座位锁定 / 支付超时 | 5 分钟 |
| 单次最多选座 / 购票 | 5 个 |
| 一人一班次限购 | 1 张（按身份证） |
| 退票手续费 | 发船前 ≥120 分钟全额退；<120 分钟收票价 20% |
| 改签限制 | 发船前 1 小时内不可改签；不能改到原班次 |
| 班次批量生成 | 单次最多 90 天 |

## 4. 接口详情

### 4.1 登录

`POST /login` 　权限：匿名

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 用户名 |
| password | string | 是 | 明文密码，后端 BCrypt 比对 |

```json
{ "username": "admin", "password": "123456" }
```

**成功响应**

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "name": "系统管理员",
    "phone": "13800000000",
    "idCard": null,
    "role": "ADMIN"
  }
}
```

> 登录成功后服务端写入 Session（键 `loginUser`），前端后续请求自动携带 Cookie，不需要手动存 token。

**失败分支**

| msg | 触发条件 |
|---|---|
| 用户名或密码错误 | 账号不存在或密码不匹配 |
| 账号已被禁用 | `user.status = 0` |
| 账号已锁定，请稍后再试 | 连续失败触发 `lockUntil` |

### 4.2 注册

`POST /register` 　权限：匿名

**请求体（User）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 唯一 |
| password | string | 是 | 最少 6 位 |
| name | string | 否 | 真实姓名 |
| phone | string | 是 | 唯一，手机号格式 |
| idCard | string | 否 | 填了则校验身份证格式 |

角色固定为 `PASSENGER`，`status` 固定为 1，前端传了也会被覆盖。

### 4.3 当前用户

`GET /api/user/current`

```json
{ "code": 0, "msg": "success", "data": { "id": 1, "username": "admin", "name": "系统管理员", "phone": "...", "idCard": null, "role": "ADMIN" } }
```

未登录返回 `{"code":1,"msg":"未登录","data":null}`（HTTP 200）。

> 虽然被 LoginInterceptor 放行到 Controller 的情况很少，但页面初始化仍要处理这个返回值。

### 4.4 用户管理

`GET /api/users?page=1&size=10&username=&role=&name=`

**返回**

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [
      { "id": 2, "username": "seller01", "name": "张三", "phone": "13900000000",
        "idCard": "...", "role": "SELLER", "status": 1, "loginFail": 0,
        "lockUntil": null, "createdAt": "2026-11-01T10:00:00", "updatedAt": "2026-11-01T10:00:00" }
    ],
    "total": 1
  }
}
```

> `password` 字段使用 `@JsonProperty(WRITE_ONLY)`，**响应中永远不出现**，前端表格不要留这一列。

**新增/编辑用户请求体（User）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 唯一 |
| password | string | 新增必填 | 最少 6 位；编辑时留空表示不改 |
| name | string | 否 | |
| phone | string | 是 | 唯一 |
| idCard | string | 否 | |
| role | string | 是 | ADMIN / SELLER / PASSENGER |

**重置密码** `PUT /api/users/{id}/password`

```json
{ "password": "newPass123" }
```

**启用/禁用** `PUT /api/users/{id}/status`：无请求体，调用即切换。

**修改个人信息** `PUT /api/profile`：body 为 User（忽略 id/role/status，后端只用 id 定位）。
**修改密码** `PUT /api/profile/password`：`{ "oldPassword": "...", "newPassword": "..." }`。

### 4.5 航线

`GET /api/routes?page=1&size=10&routeName=&departPort=&arrivePort=`

```json
{
  "code": 0,
  "data": {
    "list": [
      { "id": 1, "routeName": "大连-烟台", "departPort": "大连", "arrivePort": "烟台",
        "duration": 360, "description": "滚装客船", "deleted": 0,
        "createdAt": "2026-11-01T09:00:00", "updatedAt": "2026-11-01T09:00:00" }
    ],
    "total": 1
  }
}
```

`duration` 单位为分钟。

**新增/编辑请求体（Route）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| routeName | string | 是 | |
| departPort | string | 是 | 不能与到达港相同 |
| arrivePort | string | 是 | |
| duration | int | 是 | 必须 > 0，单位分钟 |
| description | string | 否 | |

**校验失败文案**：航线名称不能为空 / 出发港和到达港不能为空 / 出发港和到达港不能相同 / 航行时长必须大于0 / 已存在相同出发港、到达港和航线名称的航线 / 该航线下有未完成班次，不允许删除

### 4.6 船舶

`GET /api/ships?page=1&size=10&shipName=` → `Result<PageResult<Ship>>`，分页结构与全局约定一致。

```json
{
  "code": 0,
  "data": [
    { "id": 1, "shipName": "渤海明珠", "totalSeats": 200, "shipType": "客滚船",
      "description": null, "deleted": 0, "createdAt": "...", "updatedAt": "..." }
  ]
}
```

新增/编辑请求体：`shipName`、`totalSeats`（>0）、`shipType`、`description`。

> `totalSeats` 与船舶座位模板 `ship_seat` 是两回事：创建船舶时需同步生成座位模板，否则新建班次会没有座位。

### 4.7 班次

`GET /api/schedules?page=1&size=10&routeId=&shipId=&date=&status=`

```json
{
  "code": 0,
  "data": {
    "list": [
      { "id": 1001, "routeId": 1, "shipId": 1,
        "departTime": "2026-11-26T08:30:00", "arriveTime": "2026-11-26T14:30:00",
        "price": 80.00, "status": "SELLING", "soldCount": 12, "deleted": 0,
        "createdAt": "...", "updatedAt": "...",
        "routeName": "大连-烟台", "departPort": "大连", "arrivePort": "烟台",
        "shipName": "渤海明珠", "shipType": "客滚船",
        "totalSeats": 200, "remainingSeats": 188 }
    ],
    "total": 1
  }
}
```

**乘客查班次** `GET /api/schedules/search?departPort=&arrivePort=&date=` → `Result<List<Schedule>>`

只返回 `status = SELLING` 且航线未删除的班次。三个参数都可省略。

**新建班次请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| routeId | Long | 是 | |
| shipId | Long | 是 | |
| departTime | string | 是 | `YYYY-MM-DDTHH:mm:ss` |
| price | number | 是 | ≥ 0 |
| arriveTime | string | 否 | 不传则按航线时长推算 |

> 新建后状态固定为 `PENDING`，必须调 `publish` 才会进入 `SELLING`。
> 座位在创建班次时按船舶座位模板自动初始化（状态 AVAILABLE）。

**批量生成** `POST /api/schedules/batch`

```json
{ "routeId": 1, "shipId": 1, "startDate": "2026-12-01", "endDate": "2026-12-07",
  "hour": 8, "minute": 30, "price": 80 }
```

返回 `Result<List<Schedule>>`（本次生成的班次）。单次最多 90 天。

**失败分支**

| msg | 触发条件 |
|---|---|
| 该船舶在该时间段已有班次，存在时间冲突 | 同船时间重叠 |
| 班次不存在 | id 无效 |
| 航线不存在 / 船舶不存在 | 关联 id 无效 |
| 开始日期不能晚于结束日期 | 日期区间倒置 |
| 单次最多生成90天班次 | 区间过大 |
| 发船时间不合法 | 解析失败 |

### 4.8 座位图

`GET /api/schedules/{id}/seat-map` → `Result<List<ScheduleSeat>>`

```json
{
  "code": 0,
  "data": [
    { "id": 1, "scheduleId": 1001, "seatNo": "A01", "status": "AVAILABLE",
      "orderId": null, "lockTime": null, "lockUserId": null, "lockExpireTime": null },
    { "id": 2, "scheduleId": 1001, "seatNo": "A02", "status": "LOCKED",
      "orderId": null, "lockTime": "2026-11-25T10:12:00", "lockUserId": 5,
      "lockExpireTime": "2026-11-25T10:17:00" }
  ]
}
```

`lockExpireTime = lockTime + 5 分钟`，仅 LOCKED 且有 lockTime 时非空，前端直接用它倒计时。

前端渲染三态规则：

| status | 可点 | 视觉 |
|---|---|---|
| AVAILABLE | 是 | 可选 |
| LOCKED 且 `lockUserId === 当前用户 id` | 是（可取消） | 我方已选 |
| LOCKED 且非本人 | 否 | 他人占用 |
| SOLD | 否 | 已售 |

### 4.9 锁定 / 释放座位

`POST /api/seats/lock`

```json
{ "scheduleId": 1001, "seatNos": ["A01", "A02"] }
```

`POST /api/seats/unlock` 请求体相同，只释放本人锁定的座位。

**失败分支**

| msg | 触发条件 |
|---|---|
| 班次不在售票中 | status ≠ SELLING |
| 请选择座位 | seatNos 为空 |
| 最多选择5个座位 | 超过 5 个 |
| 座位号重复 | 数组内有重复 |
| 座位 A01 在该班次不存在，请刷新座位图后重试 | 座位号非法 |
| 座位 A01 已被占用，请选择其他座位 | 他人锁定 |
| 座位 A01 已售出，请选择其他座位 | 已售 |

> 锁定时长 5 分钟，超时由后端定时任务释放。前端座位图应做倒计时提示。

**请求体**

| scheduleId | Long | 是 | 班次 id |
| tickets | array | 是 | 1~5 条 |

**tickets 元素**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

| phone | string | 否 | 填了则校验格式 |

  "scheduleId": 1001,

    { "seatNo": "A01", "passengerName": "张三", "idCard": "210202199001011234", "phone": "13800000000" },

  "msg": "success",

### 4.13 退票

`POST /api/orders/{id}/refund`

```json
{ "reason": "行程变更" }
```

**规则**

- 发船前 ≥120 分钟：全额退
- 发船前 <120 分钟：扣票价 20% 手续费
- 发船后、含已检票票、未支付订单：不可退

**失败分支**

| msg | 触发条件 |
|---|---|
| 班次已发船，不可退票 | 已过发船时间 |
| 订单中含已检票船票，不可退票 | 有 CHECKED |
| 订单未支付，不可退票 | 无 PAID 票 |
| 没有可退的船票 | 全部已退/已改签 |
| 只能退自己售出的订单 | SELLER 操作他人订单 |

### 4.14 改签

`POST /api/tickets/{id}/reschedule`

```json
{ "newScheduleId": 1002, "newSeatNo": "B05" }
```

**失败分支**

| msg | 触发条件 |
|---|---|
| 船票不存在 | id 无效 |
| 仅已支付且未检票的船票可改签 | 状态不符 |
| 改签班次不能与原班次相同 | 目标相同 |
| 目标班次不在售票中 / 已发船 | 目标状态不符 |
| 发船前1小时内不可改签 | 临近发船 |
| 该身份证在目标班次已购票 | 重复购票 |
| 目标座位锁定已失效 | 座位被抢 |

> 原票状态置为 `RESCHEDULED`（不是 REFUNDED），统计口径会把改签和退票分开。

### 4.17 统计

所有统计接口返回 `Result<List<Map>>` 或 `Result<Map>`，**字段统一为 camelCase**，与实体接口一致。

| 接口 | 入参 | 返回字段 |
|---|---|---|
| `/api/stats/by-date` | start, end | statDate, saleCount, saleAmount, refundCount, refundAmount |
| `/api/stats/period` | start, end, groupBy=day\|week\|month | period, saleCount, saleAmount, refundCount, refundAmount |
| `/api/stats/by-route` | start, end | routeName, saleCount, saleAmount |
| `/api/stats/by-schedule` | start, end | scheduleId, routeName, departTime, saleCount, refundCount, income |
| `/api/stats/by-seller` | start, end | sellerId, sellerName, saleCount, saleAmount |
| `/api/stats/my-performance` | start, end | sellerId, sellerName, saleCount, saleAmount（单条） |
| `/api/stats/schedule-occupancy` | 无 | scheduleId, routeName, departTime, shipName, totalSeats, soldCount, occupancy |
| `/api/stats/route-occupancy` | 无 | routeName, avgOccupancy |
| `/api/stats/period-occupancy` | 无 | period, avgOccupancy, scheduleCount |
| `/api/stats/low-occupancy` | 无 | scheduleId, routeName, departTime, totalSeats, soldCount, occupancy |
| `/api/stats/income` | start, end | totalIncome, saleCount, refundLoss, refundCount, refundFee, netIncome, refundRate |
| `/api/stats/refund` | start, end | reason, refundCount, refundAmount, feeAmount |

说明：

- `start` / `end` 必填，格式 `YYYY-MM-DD`，闭区间（后端按 `< end + 1天` 处理）
- `period-occupancy` 的 `period` 是中文标签：`早班(06-12)` / `午班(12-18)` / `晚班(18-24)`
- `occupancy`、`avgOccupancy`、`refundRate` 单位是百分比，已 `ROUND(...,2)`
- `departTime` 统一为 ISO 格式 `2026-11-26T08:30:00`，与实体接口一致
- `statDate` 格式 `YYYY-MM-DD`
- `refund` 接口中空原因归类为 `未填写`
